# 宇宙艦隊シミュレーター（試作 v0.5）

ブラウザで動く宇宙艦隊シミュレーターの試作です。設計は**アジャイル方式**で進めており、完成品ではなく「触って、変えて、また触る」ための段階的プロトタイプです。数値・ルールはすべて調整前提です。

## サイト構成（2ページ）

- **`index.html`** — トップページ（ゲーム紹介・遊び方・ロードマップ要約）
- **`game.html`** — ゲーム本体（Three.js フル3D）
- **`three.min.js`** — 同梱の Three.js r128（MITライセンス）。無い場合は CDN（cdnjs）から読み込むフォールバック付き

公開URL（GitHub Pages）のルートはトップページで、「ゲームをはじめる」ボタンから本体へ進みます。Muse 固有の仕組みには依存していません。

## 素材（アセット）規則（本番を見越した制作ルール、2026-11-15 決定）

- **画像は WebP で統一する**：ラスター画像（顔絵・背景画・テクスチャ等）をファイルとして置く場合は WebP 形式のみ。PNG／JPG は置かない。現行ビルドの見た目は Three.js の手続き生成とインライン SVG のみで構成され、ラスター画像ファイルは存在しない（この規則は画像ファイルを導入する時点から適用される）。
- **音声は Opus で圧縮する**：音声ファイル（BGM・効果音・ボイス）を置く場合は Opus（`.opus` / `.ogg`）のみ。非圧縮 WAV や肥大した音声は置かない（sakura-mini の音声パイプラインと同じ方針）。現行ビルドの効果音は WebAudio 合成で、音声ファイルは存在しない。
- **BGM は Gemini で生成した制作素材として用意する**：音楽が必要になったら、ReminPass アーケードモードの前例どおり Gemini で生成した音源を制作素材（アセット）として用意し、Opus に圧縮してファイルとして同梱する。ゲーム実行時に AI を呼ぶ依存にはしない（公開物としてのゲーム自体は AI 不使用で、生成は制作工程だけの話）。音楽の方向性（アートディレクション）：**リードボーカル／歌詞は無し**。代わりに**バッキングコーラス**（言葉のないコーラスパッド／ハミング的なバッキング）を入れる——インストゥルメンタル＋コーラスで、宇宙を舞台にした作品らしい高級感を狙う。

## v0.3 の主な変更点

- **監督型の運航モデル**: 近未来設定では操船は艦載AIと乗員の仕事。プレイヤー（艦長）は「航海計画の承認 → 実行の監視 → 例外への判断」に専念します。手動スラスタ（WASD等）は既定UIから外し、ドロワー内の「緊急手動操縦」トグルの奥に格納（チュートリアルでは一切触れません）。
- **航行AI「イオ」と航海計画**: 各航程の前に、航行AIイオが現在の天体配置と交通から計算した航路候補（標準／省燃料／最速）を、推定Δv・所要時間つきで提示。イオの推奨案つきで、艦長が1案を選んで確定します。見積もりは惑星重力を含む実シミュレーション（実際に飛ぶのと同じ計画ポリシー）で計算しています。
- **オペレーション文化**: 出航前チェックリスト（AIと乗員が読み上げ、艦長は「出航用意よし」の一回確認）、管制による出航許可とゲート割当（「第3ゲートが空いています」→入港承認→AIが進入・接舷）、接舷前確認、復唱（指示→復唱→実行→報告）、船内時刻つき航海日誌。
- **教導士官とチュートリアル**: 専任教導士官・榊原 凛 少佐が全ての手ほどきを担当。新任艦長シナリオは「ミッション0：処女航海」（失敗なしの慣熟航行）から始まり、ミッション1でランデブー／ドッキング／相対速度／Δvを平易な言葉で1つずつ説明→即実践するステップ式チュートリアルを搭載。画面下部に常時「次にやること」を表示し、現在の操作対象はパルス発光で示します。
- **キャリアの起点は後方任務**: 新任艦長の初任ポストは3トラック（定期航路・輸送／補給艦／哨戒艇）から選ぶ。初心者はまず後方の輸送・補給で運航の基本を覚え、戦闘艦の艦長はその先、という位置づけに統一。戦隊司令／艦隊司令シナリオは「経験者向け（この階位から開始）」でチュートリアルを省略します。
- **規定航路と進入コース**: 目的地へは進入フィックスから進入コース（コリドー）に合流して接舷するのが正規手順。コース外からの高速接近は「進入コースから外れています」と警告され、クリーンな接舷とは見なされません。民間輸送船や巡行艦などのNPCが同じ航路を実際に飛び、管制アドバイザリが交通を知らせます（哨戒艇・海賊の噂への言及も）。
- **モバイル最優先レイアウト**: 操作系は画面下部の単一ボトムバー（ステータス＋次にやること＋命令ボタン）に統合。390×844（縦）／844×390（横）の両方で、はみ出し・重なりゼロを実測検証済み（横向きでは上部情報スタックを自動圧縮）。タッチターゲットは主要ボタン52px以上。

## 追加アップデート：艦長作成と「港から始まる」オープニング

- **艦長作成（新任艦長シナリオ）**: シナリオ選択のあと、港で辞令を受ける場面として艦長を作成します。全ての選択肢はデータ駆動（配列）で、項目追加は表に足すだけです。
  - 艦長名（自由入力）／顔絵ポートレート4種（色＋モチーフのイニシャルアバター。人物データとして保持し、将来の顔絵差し替えに対応）
  - 初任ポスト3種：定期航路・輸送（輸送艦「さくら」420t／貨物120t／Δv 55）、補給艦（補給艦「みずほ」520t／貨物200t／Δv 50）、哨戒艇（哨戒艇「はやて」180t／貨物20t／Δv 65）。同じオープニング骨格のデータバリアントで、初仕事の文面と管制の言及（哨戒は海賊の噂）が変わります
  - 出身・経歴6種（各1フラグ＋教導士官の紹介文が変化）／母港4種／特性8種から2つ選択（各フラグ化）／能力配分5能力（運航・補給物流・交渉・統率・人望）に10ポイント＋「おすすめ」自動配分
  - **実効している効果**：初任ポストのΔv上限、出身の数値補正（資金+30／補給+10／政治的支持+5・+3）、人望→政治的支持（1点につき+2）。それ以外の能力・特性は人物データとして保持され、将来の会話エンジンとキャリア分岐が読みます（現時点ではデータのみ）
  - **正直な注記**：母港は「提示とフレーバー＋開始連絡先フラグ」までで、実際の出発地は現行ビルドでは あおば・ステーション固定です。艦長レコードはNPCと同一形状（id／名前／顔絵／能力／特性／フラグ／名声／人間関係／艦）で保持され、localStorageにも保存されます。戦隊司令／艦隊司令の開始は作成を省略し、保存済み／既定の艦長を静かに使います
- **オープニング再構成**：物語は出航後ではなく港から始まります。順序は「艦長作成（辞令）→ 港シーン（教導士官が駅で出迎え、士官たちが対面で自己紹介し、初任の艦が名・級・トラック付きで提示される）→ 航海計画の提示 → 出航チェックリスト → 離舷・出航（ログに残る承認イベント）→ 観光航行」。港から始まるミッションは接舷状態で開始し、出航は常に艦長が承認するイベントです。港シーンは航行中の会話と同じ対話UI（話者・顔・名前）で作られており、寄港アドベンチャーパートの種です。
- **人員の種**：士官にはポスト（戦術／補給／渉外／機関、航法士は航法）が付き、ドロワーの士官タブに「配置」として表示されます。港シーンでもクルーは「着任」として紹介されます。配置の編集・募集・仕事ボードのUIは v0.4（下記ロードマップ）。

## 物理と艦船モデル（現状と正直な注記）

- 位置・速度・加速度は3次元ベクトル。重力は恒星＋惑星（ニュートン重力）を数値積分し、惑星軌道には傾斜・昇交点があります。目標艦の傾斜軌道へのランデブーは黄道面内だけでは成立しません。
- 成功条件はランデブー＝距離12未満 **かつ** 相対速度1.5以下。距離7未満で相対速度2.0超の接触は衝突（失敗）。
- 艦の噴射は現状「固定加速度＋Δv（速度変更量）予算」モデルです。**質量はまだ物理に連動していません**（計画パネルに輸送艦「さくら」の質量420t／推力2,940kN／最大貨物120tを表示し、世界観と整合させている段階）。NPCは重力軌道を飛ぶのみで操舵噴射の加減速差は未実装。本格的な質量連動はロードマップ参照。
- 命令（接近・減速・速度同調・進入合流・静止保持）は即時テレポートではなく、計算されたΔvを有限時間の噴射として執行し、Δv予算を消費します。計画の自動運航（イオ）も同じ物理・同じ計画ポリシーで飛びます。

## ローカルでの動かし方

```bash
cd space-simulator
python3 -m http.server 8000
# ブラウザで http://localhost:8000 （トップページ）→「ゲームをはじめる」
```

ファイルを直接開く場合は `game.html` を開いてください（`three.min.js` が同じフォルダに必要です）。

## ロードマップ（設計原則と将来計画）

### 進行構造とキャリア
- 正規の進行は一番下から：**一隻の艦長 → 戦隊 → 艦隊 → それ以上**。昇進＝指揮する艦と組織が大きくなること。高階位シナリオは経験者向けの近道として併置。
- キャリアパス：**民間定期航路・輸送 → 補給艦 → 戦闘艦艦長 → 戦隊司令 → 艦隊司令 …**。戦争・戦闘は後方運航を修めてから。
- 初心者の入口は2トラック：**輸送・補給トラック**（運航・兵站、本作のチュートリアル）と**哨戒トラック**（哨戒艇による航路哨戒・海賊対処＝単艦戦闘の入口、将来ミッション）。
- キャリアは一本道にしない。中盤以降は**分岐と誘い**の層：輸送の実績→補給司令部からの誘い／哨戒の武勲→駆逐艦艦長への抜擢／有力者の目に留まる→幕僚・政治方面への誘い。誘いは断っても失敗ではない。
- 2種類の門：**応募**は経験値・実績で開く（黙々と艦に乗り続けても届く）。**誘い**は名声と人間関係の好感度が要る（経験だけでは来ない）。艦内だけで過ごすと腕は上がるが人脈は育たない、という設計。

### 艦船物理
- 加速度＝推力 ÷ 総質量（船体＋貨物＋武装）。積荷の多い輸送艦は鈍重に、軽い戦闘艦は俊敏に。エンジン級で推力とΔv効率が変わる。NPC輸送船の加速も艦より鈍く見えるようにする。
- 艦の艤装・積荷カスタマイズは将来の拡張（v0.3では表示ステータスのみ）。

### 航路・交通・運航
- 規定の航路網（フィックス、標準出発/進入路、進入コース＋速度ゲート）を全艦が共有する混在交通の世界。民間船と軍艦が同じコースを飛ぶ（戦時にはこの混在が意味を持つ）。
- フェーズゲート式チェックリスト：出航前／進入前／接舷前（将来：ワープ前）。AIと乗員が読み上げ、艦長は1回の確認で承認する儀礼。
- 港の摩擦は将来「例外」から生む：ゲート満杯、キューの優先順位、優先艦への進路譲り、港長からの頼みごと——人と政治の問題として、アドベンチャーパートと誘いシステムに接続する。

### 人員マネジメントと仕事ボード（v0.4 の中核システムとして設計済み）
- **クルーは人物データ**：能力（運航／機関／補給／交渉／統率など）、特性、好感・信頼を持つキャラクターとして保持する。艦長レコードと同一の人物データ形状。
- **ポストには能力適性がある**：航法・機関・補給・通信などのポストごとに効く能力が違い、「誰をどこに置くか」が運航結果に効く意思決定になる。v0.3 では士官のポスト表示と港シーンの着任紹介までを種として実装済み。
- **募集は港で**：寄港パートで候補者が現れ、採用には名声・人脈・予算（将来）が要る。
- **仕事ボード＝「応募」の門の具体形**：港に掲示される仕事（定期便、補給契約、哨戒…）に艦長が応募する。応募は経験値・実績で開く門。一方「誘い」は名声と好感度で届く招待として別経路で来る。
- **ループ**：港（募集・配置・仕事選び）⇄ 運航（結果が実績と名声になる）⇄ 港。運航パートと寄港パートの往復がゲームの基本リズムになる。

### 寄港アドベンチャーパート（運航パート ⇄ 寄港パート）
- 航海の合間、港・ステーションで士官・後援者・商人・派閥の人々と会話し、頼まれごと・調停・情報収集・催事への参加を行う層。人脈づくり自体をシミュレーションとして組み上げる。
- 選択と振る舞いが人物ごとの好感度と公共の名声を変え、「誘い」の門を開く。運航の実績（無事故の補給記録など）も港で語られて名声に効く。部下の政治的動き（噂・派閥・ライバル）もここで可視化される。

### 汎用会話・人間関係エンジン（データ駆動で作る）
- 一場面ごとの作り込みではなく、汎用エンジン＋データ追加でコンテンツを増やす方針。
- **キャラクターデータ**：id、名前、役割/派閥、性格特性、関心事、素の disposition、プレイヤーへの関係状態（好感度／信頼／敬意は別軸）、過去のやり取りの記憶フラグ。**顔絵は1人1枚**をデータ内に参照として持ち、後から差し替え可能にする（全身絵・表情差分・モーションは不要）。
- **会話データ**：発言者・本文・選択肢を持つノード列。各選択肢に条件（関係値・名声・フラグ・階級・過去イベント）と効果（好感度/信頼/名声の変化、フラグ設定、誘い・任務の解放、噂の拡散）を持たせる。士官・後援者・商人・ライバルまで同一エンジンで扱う。
- **関係シミュレーション**：同じ話題でも性格・関心で反応が変わり、恩と侮辱は記憶され、人づてに噂が伝播する（ある港での行いが別の港の評判を変える）。
- 構築順序：エンジン先行、サンプル2〜3人で汎用性を証明してからデータを増やす。

### オンライン化（NPC＝人間、単一エンティティモデル）
- 艦・艦長・士官・港の人物は、誰が駆動するか（NPCスクリプト／自軍部下のAI／他の人間プレイヤー）によらず**同一のエンティティ/エージェントモデル**で扱い、世界側は区別を表示しない。航路の交通、港にいる艦、寄港先の人物のどれもが、その3つのどれでもありうる。
- だからこそ世界観は「AIによる自動運航＋事前命令（standing orders）」に寄せる：他プレイヤーの艦隊は本人がオフラインでも命令どおり飛び続け、距離と時間尺度の差を越えて非同期に共有世界が成立する。
- **世界時計は全員で共有され、固定である。個人の時間早回しは存在しない。** もし各プレイヤーが私的に時間を早回しできたら、他プレイヤーとの遭遇・ランデブー・港の順番待ち・期限がすべて破綻するため。長い航行は、艦載AIの自律運航・事前命令・非同期の報告と航海日誌（命令を出して離れ、戻ってきたら日誌で結果を読む）で吸収する——世界観が「AI運航と委任」に寄っているのはこのためでもある。
- 試作版の「待機（時間を進める）」は、シングルプレイのローカルな便宜機能にすぎない。作中の技術としては描かず、オンライン版には持ち込まない。
- **ホスティング移行のトリガー**：試作期間は静的ホスティング（GitHub Pages）で高速に回す。**オンライン実装を開始するタイミングで Firebase へ移行する**（Hosting＋Firestore＋Auth。物理の権威は Cloud Run 等のサーバ側に置く）。アカウント・共有世界・事前命令で飛び続ける艦隊といった、サーバが要る要素はすべてこの移行とセット。
- **移行チェックリスト（リポジトリの公開設定）**：Firebase 移行の実施時に、GitHub リポジトリ（MrHiraiwa/space-simulator）を **Public → Private へ変更する**（2026-11-15 決定）。公開の受け口は Firebase Hosting 側へ移り、GitHub Pages は不要になるため。**試作期間中は Public のまま**とし、変更は移行作業の一部として行う（先行して閉じない）。
- **アカウント管理（オンライン期に必須）**：オンライン期はアカウントが前提になる（Firebase Auth 想定）。プレイヤーの艦長キャラクター・進行度・事前命令艦隊はアカウントに紐付く。試作期間はテストの摩擦をなくすため**意図的にアカウント無し**（ローカル保存のみ）で回す。オンライン期の未決事項（今は決めない）：1アカウント＝艦長1人か、複数キャラクター可か／登録前のゲスト・体験プレイを認めるか。

### 世界の時間とワープ（フィクション規則）
- **作中で移動時間を短縮できる手段は、恒星間ワープだけ**である。ワープは恒星間に限る。
- 星系内に時間短縮の技術は存在しない。系内の速さは物理とΔvで決まる：速く行きたければ推進剤を多く燃やす（計画の「最速」案がΔvを多く消費するのが、そのトレードオフ）。これが系内航行のゲーム性そのもの。
- 時間加速はプレイヤー側の都合（当直への引き継ぎ＝待機）であって、艦や艦長の能力ではない。いかなるシステムも、作中の時間操作を示唆してはならない。

### キャラクターの発言規則（メタ発言の禁止）
- **作中キャラクター（教導士官・航行AI・士官・管制・NPC艦長）は、メタ発言を一切しない。** ゲーム・UI・ボタン・画面・プレイヤー・セーブ・時間加速の仕組みなどへの言及は台詞に入れない。
- 用語の教学（教導士官の役割）は、世界の/運航上の事実として語る（例：Δvは「あとどれだけ噴射できるか」という艦の能力であって、ポイントではない）。
- 試作・システム都合の説明（待機/早送り、海図AUTOのUIとしての挙動、設定など）は、帰属のないシステム/UIテキストが担う。チュートリアル文でも、台詞は「　」内の引用部に作中の言葉だけを置き、操作説明は【システム】注記として分離する。
- 航行AIの海図表示切替の報告（例：「接近する交通が増えたため、近傍表示に切り替えました」）は、艦の表示装置の仕事として作中の業務報告であり、許容される。ただしゲームシステムへの言及はしない。

### 巡航時間＝艦内生活パート
- 巡航中の待ち時間は、プログレスバーを見つめる時間にしない。艦長は当直に艦を任せ、艦内生活を送る：**乗組員と話す**（会話・人間関係エンジンの最初の実働形。台詞は人物データと状況で変わり、信頼/好感の小さな変化を記録する）、**艦内を見回る**（艦橋・機関室・貨物庫・通信室・居住区・観測窓。在室者は配置から決まる）、**小さなオペレーション**（機関点検・艦内見回り・当直訓練。艦内時間を使い、報告と航海日誌への記録が返る）。いずれも航行を止めずに並行して行える。
- オンライン版（実時間の共有時計）では、この艦内生活こそが待ち時間の体験になる。時間操作で埋めるのではなく、艦内生活で埋める設計。
- 艦内を歩き回れる完全なインテリアは後段のレイヤー。現行は区画リスト＋フレーバー＋在室者のパネルが種。

### 出発・到着オペレーション
- 出発と到着は、チェックリスト（書類）だけで終わらせず、物理フェーズとして実行する：**離舷**（係留解除・内部電源切替の読み合わせ、艦が実際にステーションから離れる）→ **港内航行**（管制の指示のもと制限速度で出域点へ。港の混雑が速度制限の理由になる）→ **出域**（管制が航路管制へ移管し、ここから本航行の噴射が始まる）。
- 到着はその鏡像：入域 → 進入コース合流 → **接舷作業**（最終進入 → 接舷 → 係留・到着手続き）を独立フェーズとして報告してから、到着/達成の報告に進む。
- 計画実行の状態表示はこれらのフェーズも含めて現在フェーズを示す。

### 海図と表示範囲
- 海図は3段階の表示範囲を持つ：**港内**（ゲート・接舷艦・沖待ち・作業艇）、**近傍**（航路・進入コース・近傍交通）、**広域/星系**（惑星・航路・目的地）。コンタクトと自艦がプロットされ、近い範囲では名前ラベルが付く。
- 既定は**自動**：艦の航行AIが運航支援の一環として表示範囲を管理する（接舷/港内作業→港内、進入→近傍、巡航→広域。近傍のコンタクト密度が高いと一段寄せる）。切替時にはAIが理由を一言報告する（黙って変えない）。
- 艦長は任意の範囲を指定でき、その指定は「自動（AIに任せる）」に戻すまで保持される（艦長の上書き）。
- 3Dカメラの推奨距離も同じ段階に連動させる（港内=寄る、巡航=引く）。ホイール操作で即座に手動へ戻る。

### 航行AIの名前
- 航行AIはシステムのラベルではなく、艦に属するキャラクターである。艦長作成時に、候補から選ぶか自由入力で命名する（既定候補に「イオ」を含む）。計画画面の見出し・台詞・海図の切替報告など、AIへの言及はすべて選んだ名前で行う。
- AIは**艦に属する**。将来、艦長が別の艦へ転属する場合は、その艦のAI（別の名前・別の性格）になるのが原則。艦長が自分のAIを連れて行ける仕組みを持たせるかは、未決の設計課題として残す。

## v0.5 の変更点（情報設計の見直し）

### 静かな画面：単一メッセージ面＋タスク方式
- 発言は1か所だけに表示する（士官の台詞とチュートリアルの重複表示を解消）。メッセージ面は優先度つき（警告＞士官＞案内）で、閉じれば細い「次の行動」行だけが残る。
- あらゆる画面要素は「タスク」として出し閉じできる。閉じたタスクは下部のタスクバー（計画／海図／交通／日誌のチップ）に最小化され、未読・判断待ちはチップ上の件数で示される。タスク同士は共存でき（例：海図＋計画は計画が下部シートのコンパクト形になる）、開閉状態は端末に保存される。
- 人物の会話・重要場面はタスクではなく「カットイン」として最上位レイヤーに割り込む。カットインが閉じれば、開いていたタスクの配置はそのまま戻る。レイヤー順序は固定：基準ビュー（3D／艦内）＜タスク＜カットイン。
- 手動命令ボタンと距離・相対速度の読み出しは、艦長に判断がある局面（速度同調・合流の承認、手動修正時）だけに表示する。AI運航の巡航中は出さない（監督型モデル）。
- カメラ操作と通信ティッカーは3Dビュー上のオーバーレイに移し、巡航中の3D表示は画面高の5割以上を確保する。
- 半透明オーバーレイ（確定した不透明度）：メッセージ面 rgba(8,15,32,0.66)＋blur 10px／作戦バナー 0.55／次の行動 0.60／管制ドック 0.84＋blur 14px／海図の地 0.55・箱 0.88。明るい惑星・恒星の前でも文字が読めることを実機スクリーンショットで確認済み。

### 話者と場所の存在感
- 発言する人物は、名前＋台詞の横にシルエット（SVGバスト）を表示する。バリエーションは役職・体格・髪型で分け、航行AIはホログラム風の非人間デザイン。管制などの音声通信は声のみとし、ログ側で 📡 と明示する。シルエットは人物レコードの `silhouette` フィールドでデータ駆動（将来の顔絵差し替えと同じ枠）。
- 艦内の各場所（艦橋／艦長室／通路／機関室／貨物庫／通信室／居住区／観測窓）と港の内景には背景画（SVG）があり、見回りで移動すると背景が変わり、会話はその場所の背景の上で行われる。場所レコードの `bg` キーでデータ駆動。
- 航行⇄艦内は常時表示の切替で1タップ。艦内モードにも細い航行ステータス行と報告通知（タップで航行へ戻る）が残り、カメラ・海図・計画の状態は切替で一切リセットされない。

### NPCの向き・航路表示
- 全ての移動体は速度ベクトル方向に船首を向ける（港内の接舷船・待機船・作業艇・定期便も実移動から姿勢を取る）。実測：修正前は港内船で最大約172°のずれ → 修正後は全船0°。
- 海図は各コンタクトの相対進路ベクトル（矢印つき）を描き、3Dでは近距離（200以内）の交通だけに淡い進路ラインを表示する。管制の交差注意は、実際に接近しているコンタクトと実測の接近形状に基づいて発する。

### 到着の物理（ランデブーは相対速度ゼロが条件）
- 計画推定は実行系と同じ航法ポリシーを飛ばして作るため、計画の到着時相対速度は計算上の性質として ≈0 になる。計画画面は Δv を「出発噴射／到着噴射」に分けて表示し、到着時（または通過時）の相対速度も明示する。
- 接舷の成立条件は距離＜12 かつ相対速度 ≤1.5。それを超えた接近はフライバイとして警告され、ステーション・惑星への高速接触（相対速度＞2.0）は衝突として作戦失敗になる。衝突コースは予測最接近に基づいて管制が警告する。教導では「場所に着くだけでは到着ではない。相手と同じ速さで着くことが到着」と教える。

### 出現と時間の連続性
- ポップイン禁止：ワープ到着は星系外縁の到着点に現れて管制が捕捉を報せ、海図コンタクトは近傍空域への入域を検知した時点で現れる。港の船々は開幕時点の「もともと居た」初期状態として成立している。
- 時間は全速度で連続して流れる（物理はサブステップ積分）。待機（早回し）は時間を飛ばす仕組みではなく、ログ・報告は発生した船内時刻にそのまま積み上がる。ログの時刻は船内時（日＋時分秒）で記録し、所要時間・ETAは「時間／日」の自然単位で表示する。

## v0.5 追補（計画＝運航文書／航路／会話と見回りの場面化／時間コスト移動）

### 航海計画は運航文書
- 計画パネルは3案のカードだけで終わらない。選んだ案について、承認前に全文を検証できる：**航路**（航路点の並びと ETA を船内時で表示）、**噴射計画**（出発噴射／巡航（修正噴射）／減速／速度同調／進入合流・最終接近の区間ごとに、予定時刻・Δv・累計）、**推進剤予算**（計画消費／現在残量／到着時残量見込み／予備判定）、**到着条件**（到着時相対速度と接舷可否）、**航路上の注意**（港内の制限速度、近傍の実交通）。推定は実行系と同じ航法ポリシーを飛ばす推定器が区間（legs）まで返す。
- 艦長のレバーは監督レベルの2つが実働する：**優先**（バランス／到着時刻／推進剤）で AI 推奨が再導出され、**予備**（5%／10%／20%）で予備を割る案に「予備不足」が付く。出発時刻ウィンドウの選択は、目標の将来位置での再推定が必要なため次便に staged（ダミーの操作は置かない）。
- 航路は計画の第一級要素：案ごとにコースが違う（標準＝公示航路、省燃料＝低推力コース、最速＝直航コース）。海図には自艦の航路（軌道線＋航路点ラベル）が計画と連動して描かれる。
- 航行中、計画は「追跡文書」として生きる：計画タスクを開くと現在区間（▶）・航路点の通過状況と次の ETA・実績消費 vs 計画が読める。推進剤消費の乖離が 15% 超かつ 2 超になると航行 AI が報告し、計画チップに印が付く。

### 会話と見回りは「場面」
- 人との会話は小さな窓では行わない。専用の場面（カットイン層）が開き、場所の背景いっぱいに話者のシルエットが大きく立ち、台詞と選択肢が場面の文法で出る。終われば直前のタスク配置にそのまま戻る。管制の注意や AI の一行報告のような「呼びかけ」は会話ではないので従来どおり小さい面に残す（切り分け規則：プレイヤーが関与し選択と関係効果がある対話＝場面、一方的な通報＝呼びかけ）。
- 艦内見回りも場面：区画は背景＋在室者のシルエット＋その場所の状態（艦橋は航行状況、機関室は機関状態、貨物庫は積荷・補給残量）で描かれ、点検などの作業はその区画の中で行い、結果はその場で報告される。艦内タブは「誰がどこにいるか」の索引（タスク）として残る。

### 艦内移動にも時間がかかる
- 艦内は小さなグラフ：区画間の移動は通路を経て、距離に応じた船内時間を消費する（輸送艦「さくら」：艦橋⇄艦長室 1分、艦橋⇄機関室 3分（通路1分＋2分）、機関室⇄貨物庫 1分 など）。移動中も時計は選んだ倍率で流れ続け、航行も続く。途中で報告が入れば通路で通信として受け取れ、航行画面へ対応しに行くことも、歩き続けることもできる。引き返し・行き先変更も可能。
- 会話は1回 1.5分、作業は機関点検 6分／当直訓練 5分／見回り 3分の船内時間を消費し、効果とログは完了した時刻に記録される（時間を飛ばさない）。艦長の現在位置は実状態として保持され、場面を閉じても移動・作業は時間どおりに進む。

## スケール監査と星系設計（設計済み・定数の実装は次便）

現行ビルドの実測（ソル系）：恒星 μ=20000、惑星の軌道半径 95／150／215／300 → 公転周期 41秒／82秒（居住惑星）／140秒／231秒。つまり居住惑星の「1年」は現実の82秒であり、×1の時計は正直ではない。これが「惑星が速すぎる」「リアルタイムに思えない」の数値的な正体。

方針は本人の指定どおり「速度はそのまま、距離だけ大きくする」：全速度・加速度・Δv を現行のままに保ち、軌道半径を k 倍、恒星 μ を k 倍にする（v 一定・r×k ⇒ μ×k、周期は ×k）。居住惑星の周期を1年に合わせると k ≈ 386,700、μ は 7.73×10⁹、半径は 3.67×10⁷／5.80×10⁷／8.31×10⁷／1.16×10⁸ になる。Δv の経済はこの変換で不変（速度だけの関数）で、惑星間遷移は現在の速度のままでは数週間〜数か月級になる（最速の隣接ホップで約20〜40日）。実装には浮動原点レンダリング、推定器の時間軸スケーリング、ステーションの惑星周回化、ワープ倍率の拡張が前提になるため、本便では設計を確定し、定数の実装は次便とした。

## 既知の制限（v0.5）

- **星系スケールの実数化は未実装（設計のみ確定）**：現行コードの定数は今も玩具スケール（居住惑星の公転周期は実測82秒）。「速度はそのまま・距離だけ×k」の設計と設計星系表は上記「スケール監査と星系設計」に確定済みだが、定数の実装（浮動原点レンダリング・推定器の時間軸スケーリング等が前提）は次便。
- **地表港の降下・上昇オペレーションは未実装**：港ネットワークの設計とデータ（`PORT_NETWORK`）はあるが、地表港はまだ海図の目的地として描かれていない。設計は上記に確定済みで、実装は次便。
- 質量連動の物理（質量÷推力で加速度が変わる）は表示のみで未実装。艦の艤装、戦闘、哨戒トラックのミッション深度も未実装（上記ロードマップ）。
- 計画の艦長レバーのうち「出発時刻ウィンドウの選択」は未実装（優先・予備の2レバーは実働）。目標の将来位置での再推定が必要なため次便に staged。
- 惑星同士の重力相互作用は省略（惑星は恒星重力のみで運動し、自艦・NPCは恒星＋惑星の重力を受けます）。相対論効果は未実装。
- 艦長データとUI設定は端末（localStorage）に保存されるが、航海途中のセーブ／ロードはない。
